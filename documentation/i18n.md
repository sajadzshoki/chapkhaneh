# Internationalisation

## Configuration

Configured in `nuxt.config.ts` via `@nuxtjs/i18n` v10.

| Locale | Code | Direction | URL prefix |
| --- | --- | --- | --- |
| Persian | `fa` | RTL | none (default) — `/services` |
| English | `en` | LTR | `/en` — `/en/services` |

Strategy is `prefix_except_default`, so Persian URLs stay clean. The user's
choice is remembered in the `mb_locale` cookie.

## Direction handling

`useLocaleHead()` in `app/app.vue` sets `<html lang>` and `<html dir>` from the
locale definition. Nothing else needs to know about direction, because the
layout uses **CSS logical properties** throughout: `ps-*`/`pe-*`, `ms-*`/`me-*`,
`text-start`/`text-end`, `border-s`/`border-e`.

The one case that needs help is directional iconography; `.flip-x` in
`main.css` mirrors an icon under RTL.

## Translation files

`i18n/locales/fa.json` and `i18n/locales/en.json`. Both files have an identical
key structure — keep them in sync when adding keys.

Top-level namespaces:

`meta` · `nav` · `common` · `states` · `home` · `services` · `pricing` ·
`equipment` · `portfolio` · `about` · `faq` · `contact` · `quote` · `footer` ·
`admin`

`admin.*` is populated ahead of the admin panel so phase 3 needs no
translation work in the shell.

## Two kinds of text

This is the important distinction in the codebase:

**1. UI chrome → translation files.**
Labels, buttons, table headers, validation messages. Accessed with `$t()`:

```vue
<UButton>{{ $t('common.getQuote') }}</UButton>
```

**2. Content → `Localized<T>` objects in `shared/data/`.**
Service descriptions, equipment specs, FAQ answers. These carry both languages
in the data itself:

```ts
title: { fa: 'چاپ افست', en: 'Offset Printing' }
```

Render them with the `useLocalizedContent()` helper:

```vue
<script setup lang="ts">
const { L } = useLocalizedContent()
</script>
<template>
  <h3>{{ L(service.title) }}</h3>
</template>
```

Why the split? Content lives in the database and is edited by the client
through the admin panel; UI chrome does not.

The `admin.*` namespace covers the whole admin panel — navigation, actions,
field labels, filters, validation messages, dialogs, toasts, empty states and
the human-readable quote statuses. The panel is bilingual like the public site,
so **both locale files must stay the same size**; a missing Persian key would
show the operator an English string or a raw key. Database enum values are
never rendered directly: `admin.quotes.statuses.REVIEWING` maps `REVIEWING` to
«در حال بررسی».

Because admin routes are excluded from i18n URL routing (`defineI18nRoute(false)`,
so no `/en/admin` twin exists), the panel switches locale in place through
`useAdminLocale` and persists it in the `mb_admin_locale` cookie, which is read
during SSR so the first paint has the right language and direction.

## Gotchas

- `@` in a translation value must be escaped as `{'@'}` — vue-i18n treats a bare
  `@` as linked-message syntax and throws a compile error.
- Numbers should go through `formatNumber()` / `formatPrice()` in
  `app/utils/format.ts` so Persian gets Persian digits and correct grouping.
- User input may contain Persian digits — `toAsciiDigits()` normalises it before
  validation or storage.

## Adding a locale

1. Add the entry to `i18n.locales` in `nuxt.config.ts` (with `dir`).
2. Create `i18n/locales/<code>.json`.
3. Extend `LocaleCode` in `shared/types/common.ts` — TypeScript will then flag
   every `Localized<T>` object in `shared/data/` that needs the new language.
